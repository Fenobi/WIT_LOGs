## 1. 主控 MCU

### 1.1 约束回顾

- ≥2 路 CAN FD（FDCAN 外设，兼容经典 CAN）；
- 高满载写入：需要大 RAM 缓冲 + 高吞吐存储接口（SDMMC 原生优先，SPI-SD 仅作备选）；
- 路线：先开发板后画板，开发板需便宜易得。

### 1.2 候选对比

| 维度 | **STM32H723VGT6** ✅ | STM32G474RET6 | 备注 |
|------|--------------------|---------------|------|
| 内核 | Cortex-M7 **@550 MHz** | Cortex-M4 @170 MHz | H7 处理/搬运能力强 3 倍+ |
| RAM | **564 KB**（128KB DTCM + 432KB，带 ECC） | 128 KB | 多路满载缓冲的决定性优势 |
| Flash | 1 MB | 512 KB | — |
| FDCAN | **3 个**（2× FDCAN + 1× TT-FDCAN，可作普通 FD 用） | 3 个 | 2 路记录 + 1 路硬件预留 |
| FDCAN 共享 Message RAM | 2560 words（三实例分partition，M1 定量分配） | 同机制（容量较小） | 关键设计点，见 M1 |
| SD 卡接口 | **2× SDMMC**（原生 4-bit） | 无 SDMMC（只能 SPI，~0.5–1 MB/s） | 满载写入的硬指标 |
| USB | USB FS/HS（HS 需外接 ULPI PHY） | USB FS | Q4 在 M1 评估 |
| 工作频率/功耗 | 高性能、功耗较高 | 低功耗 | 记录仪非电池为主，不敏感 |
| 开发板 | **WeAct H723VGT6 核心板**（淘宝 ¥88–115，现货充足） | NUCLEO-G474RE（~¥100） | 两者都易得 |
| 生态 | CubeMX/HAL 支持 FDCAN+SDMMC 成熟 | 成熟 | — |

### 1.3 结论

**主控 = STM32H723VGT6，开发板 = WeAct H723VGT6 核心板。**

理由：唯一同时满足「≥2 路 FDCAN + 原生 SDMMC + 500KB 级 RAM 缓冲」的廉价候选；G474 无 SDMMC，满载 2 路时 SPI-SD 写入吞吐成为瓶颈。第 3 路 FDCAN（TT-FDCAN 作普通 FD）为 v1.x 扩展预留（Q8）。

> ⚠️ 已淘汰：STM32F103 / F407（bxCAN 仅经典 CAN，无 FDCAN）。

## 2. CAN 物理层

| 项 | 选型 | 说明 |
|----|------|------|
| 收发器 | **TJA1044GT/3** 或 **MCP2562FD**（均支持 FD 数据段 5 Mbps+）×2 | ⚠️ **经典收发器不可用**：TJA1050 / MCP2551 / SN65HVD230 不支持 FD 高速率，购买时严格核对型号 |
| 开发板阶段 | 2× FD 收发器模块（淘宝有 TJA1044/MCP2562FD 模块）+ 杜邦线 | WeAct 核心板不带 CAN 收发器，需自备 |
| 总线防护（自制板） | 每路：共模电感 + TVS（如 PESD1CAN） | 车载/工业环境 ESD 与共模抑制 |
| 电气隔离 | 光耦/隔离收发器（TJA1052i/ADuM 系列） | v1 不做，PCB 预留空间给 v2 隔离版 |
| 终端电阻 | 板载 120Ω ×2 路，跳线/拨码投切 | FR-14 |
| 精度增强 | 收发器时钟同步、晶振方案 M1 定（CAN 需要高精度时钟源，典型 ±0.1% 以内即可满足 FD） | M1 |

## 3. 存储

| 项 | 选型 | 理由 |
|----|------|------|
| 介质 | microSD ≤32GB，**推荐高耐久/监控级卡** | 满载 ~2 MB/s 级持续写入（M1 精算），普通卡寿命与掉速风险高 |
| 接口 | **SDMMC1，4-bit**（自制板）；开发板阶段若核板无 SD 座则用 SPI-SD 模块先行、移植层做抽象 | 适配层隔离 SPI/SDMMC 差异 |
| 文件系统 | **FatFs R0.15** | 事实标准；支持 f_sync 掉电策略 |

**掉电保护策略**（M1 细化）：环形 RAM 缓冲 + 批量块写 + 定时 f_sync + 文件头/索引立即 sync。

## 4. 时间与时间戳

| 方案 | 说明 |
|------|------|
| RTC：片内 + LSE 32.768k 晶振 + 备份电池（CR1220） | 秒级绝对时间，±2 s/天 |
| 微秒级：**32-bit 定时器 @1 MHz 自由计数** | 每帧入缓冲时硬件时间戳打点（CAN RX 回调读计数器），与 RTC 秒交界对齐——M1 设计对齐算法与回绕处理 |

## 7. 软件平台：RT-Thread 标准版（✅ 2026-11-09 决策）

> 备选对比结论：FreeRTOS（CubeMX 集成最顺）> 裸机 > ThreadX/Zephyr；最终选 **RT-Thread**，理由：中文文档生态最好、FinSH shell 现成（省去自研调试 shell）、DFS 文件系统 + SDIO 设备框架开箱即用。

- 内核：**RT-Thread 标准版 5.x**（Apache-2.0），不用 Nano（需要 FinSH 与设备/文件系统组件）；
- 集成方式：CubeMX 生成 H723 基础工程（时钟树/外设初始化）+ RT-Thread 内核源码目录加入 EIDE 工程（M2.1 完成首次集成并留验证记录）；
- 线程模型（M1 细化优先级与栈尺寸）：

```text
快路径（中断，零调度延迟）：
  FDCAN RX ISR ──→ 无锁环形缓冲 + 时间戳打点 ──通知──→ 写入线程

RT-Thread 线程（慢路径）：
  sd_writer   低优先级   批量块写 + fsync（SD 卡偶发 50~200ms 长阻塞不影响其他线程）
  usb_proto   中优先级   CDC 帧流上行 + 主机命令解析
  app_main    低优先级   记录状态机 / 配置 / LED按键 / IMU / 串口扩展
  finsh       低优先级   调试命令行
  tidle/timer 系统线程
```

- 文件系统：优先 RT-Thread **DFS + SDIO 设备框架**（bsp 自带 drv_sdmmc + elmfat）；保留存储适配层，若 H7 SDMMC 驱动兼容性或性能有问题，回退裸 HAL + FatFs（M2.3 实测定）；
- 工作量影响：M2.1 集成内核 +2h，M2.2 调试基建因 FinSH 现成 -2h，总体持平；
- ⚠️ RTOS 不会自动解决的问题（M1 专项设计）：H7 **D-Cache 与 DMA 一致性**（缓冲 32B 对齐 + cache 维护，或 MPU 非缓存区）、HAL 时基与 OS tick 分离、时间戳服务与系统时钟对齐。

分层结构不变（细节留 M1）：

```text
┌─────────────────────────── app ────────────────────────────┐
│  记录控制状态机 / 配置管理 / LED按键  │  主机协议解释器      │
├─────────────────────── middleware ─────────────────────────┤
│  CAN 帧环形缓冲(按通道)  │  SD 写入管线(批量块写+sync)       │
│  DFS/FatFs 适配层        │  USB CDC 流控(过滤/抽样)          │
│  时间戳服务(RTC+1MHz计数)│  配置存储                         │
├──────────────────────── drivers ───────────────────────────┤
│  FDCAN ×2 (+filter bank) │ SDMMC │ USB │ IMU │ UART │ LED/KEY │
└────────────────────────────────────────────────────────────┘
```

- CAN 路径纪律不变：RX 中断内只做无锁入队，数据通路单方向，确保中断路径最短（M1 给出最坏中断频率计算）。
