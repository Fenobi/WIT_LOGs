## 1. 项目概述

### 1.1 背景与定位

开发一台高性能 CAN/CAN FD 数据记录仪：

- **同时采集 2 路 CAN FD 总线**（完全兼容经典 CAN），逐帧带高精度时间戳写入 SD 卡；
- 通过 **USB 向上位机输出实时数据流**并提供配置/控制协议；数据分析（DBC 解码、统计、图形、过滤规则管理、报文发送）由**上位机软件**完成，设备专注"可靠采集与记录"；
- 硬件与软件框架预留扩展：**串口数据记录通道**（RS485/TTL）与 **IMU 传感器记录**。

### 1.2 项目目标

1. 开发板上实现全部固件功能：2 路 FD 满载零丢帧记录（M2 退出标准）；
2. 自定义 PCB 设计、打样、焊接、固件移植成功（M4）；
3. 72 小时连续运行 + 掉电测试通过（M5）；
4. 全流程文档可复现（贯穿全程）。

### 1.3 名词定义

| 术语 | 含义 |
|------|------|
| 记录段（Session） | 一次连续记录，对应 SD 卡上一个数据文件 |
| 满载（100% busload） | 总线上连续无空隙的帧流，是记录仪的极限工况 |
| 仲裁段/数据段 | CAN FD 帧中速率切换的两段；典型配置 500 kbps / 2 Mbps |
| 上位机 | 与记录仪 USB 连接的电脑端软件（本仓库 tools/ 提供 CLI 形态） |

## 2. 用户场景

1. **车载/工业总线记录**：设备接入车辆或工业设备的 2 路 CAN，长时间（数天）无人值守记录，事后取卡用电脑解析分析；
2. **实时监控调试**：USB 连电脑，上位机实时显示总线上报文流，DBC 解码物理值，下发发送报文/过滤配置；
3. **多源同步记录**：扩展通道同时记录串口设备数据与 IMU 运动数据，时间戳与 CAN 帧同一时基，便于关联分析。

## 3. 功能需求

> 优先级：★★★ 必须 / ★★ 应该 / ★ 可选（v1.x）。

| 编号 | 需求 | 优先级 | 说明 |
|------|------|--------|------|
| FR-01 | 2 路 CAN FD 采集 | ★★★ | FDCAN 外设 ×2；支持经典 CAN（≤1 Mbps）与 CAN FD（仲裁 ≤1 Mbps、数据段 ≤5 Mbps）；标准帧/扩展帧；每路独立波特率配置 |
| FR-02 | 高精度时间戳 | ★★★ | 每帧附时间戳：RTC 秒 + 硬件定时器微秒级偏移；帧间相对精度 ≤ 100 μs |
| FR-03 | SD 卡持久记录 | ★★★ | SDMMC + FatFs；记录段文件化；满载工况零丢帧（见 NFR-01） |
| FR-04 | 掉电保护 | ★★★ | 记录中掉电不损坏文件系统；已写数据完好；上电可续记/新建段 |
| FR-05 | 记录控制 | ★★★ | 按键开始/停止；上电行为可配置（自动记录/等待命令）；LED 状态指示（待机/记录/卡满/错误） |
| FR-06 | USB CDC 实时数据流 | ★★★ | USB 虚拟串口输出实时帧流（含通道号+时间戳）；高负载时支持过滤/抽样降级（完整性以 SD 记录为准） |
| FR-07 | 主机控制协议 | ★★★ | 上位机可：查询状态/版本、设置波特率、配置帧过滤（FDCAN filter bank）、开始/停止记录、下发时间同步 |
| FR-08 | CAN 发送 | ★★ | 上位机下发单帧/周期帧发送请求，设备执行（用于总线仿真与响应测试） |
| FR-09 | 帧过滤 | ★★ | 硬件过滤配置由上位机下发，支持 ID 列表/范围屏蔽 |
| FR-10 | 串口记录扩展 | ★★ | UART/RS485 通道 ×1，数据与 CAN 同时间戳记录；v1 硬件预留 + 软件通道框架，具体协议解析属 v1.x |
| FR-11 | IMU 记录 | ★★ | I2C/SPI IMU（加速度+陀螺仪）按固定速率记录，同时间戳；v1 可选启用 |
| FR-12 | 配置持久化 | ★★★ | 波特率/过滤/自动记录等配置存 SD 卡配置文件，掉电保留 |
| FR-13 | 记录段分卷 | ★★ | 单文件达阈值（如 256 MB）自动分卷；支持记录段索引便于上位机遍历 |
| FR-14 | 终端电阻 | ★★ | 每路 CAN 板载 120Ω 终端电阻，跳线/继电器可控（自制板） |
| FR-15 | OLED 本地显示 | ★ | v1 不做（M0 决策），预留 I2C 接口 |

## 4. 非功能需求

| 编号 | 类别 | 指标 |
|------|------|------|
| NFR-01 | 记录吞吐 | 2 路 × (500 kbps / 2 Mbps FD) 100% 满载，持续 ≥30 min，**零丢帧**（M1 定量设计缓冲与写入管线后细化单路数据段 5 Mbps 的目标） |
| NFR-02 | 时间戳精度 | 帧间 ≤100 μs；绝对时间经上位机时间同步后偏差 ≤2 s/天（RTC） |
| NFR-03 | 存储容量 | microSD ≤32 GB（推荐高耐久型）；满载估算写入 ~2 MB/s 量级（M1 精算），32 GB 可连续记录 ~4 h 满载、数天常规负载 |
| NFR-04 | 供电 | v1 开发板阶段 USB 5V；自制板支持 9~24V DC 输入（车载/工业电源）+ USB |
| NFR-05 | 电气防护 | 自制板 CAN 接口 TVS + 共模抑制；总线错误（bus-off）自动恢复并计数上报 |
| NFR-06 | 工作温度 | 0 ~ 70 °C |
| NFR-07 | 成本 | 自制板 BOM 目标 ≤150 元（不含卡） |
| NFR-08 | 可维护性 | 固件分层（drivers/middleware/app）；主机协议文档化、版本化 |

## 6. 外部接口需求

| 接口 | 用途 | 说明 |

## 7. 验收标准

1. ✅ 2 路 CAN FD（500 k/2 M）100% 满载注入 ≥30 min，SD 记录帧数 == 注入帧数（零丢帧），每路独立验证；
2. ✅ 经典 CAN（500 kbps）记录正常，帧格式解析正确；
3. ✅ USB CDC 实时流可被上位机脚本接收并转为标准格式（CSV/ASC）；主机协议（配置/过滤/时间同步/状态）全功能可用；
4. ✅ SD 卡数据可直读，`tools/` 脚本正确解析为 CSV，字段完整；
5. ✅ 记录中拔电 ≥10 次：文件系统零损坏、已写帧完好；
6. ✅ 时间戳：帧间 ≤100 μs（逻辑分析仪对拍）；RTC 偏差 ≤2 s/天；
7. ✅ 72 h 连续运行无死机、无丢帧；
8. ✅ 全部 ★★★ 需求项通过测试用例（M5 计划覆盖）。
