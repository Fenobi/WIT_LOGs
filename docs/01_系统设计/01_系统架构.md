## 1. 系统总览

```text
                        ┌──────────────────────────────────────────────┐
  CAN1 H/L ──┐          │                  STM32H723VGT6               │
  CAN2 H/L ──┴─[FD收发器]─┤  FDCAN1/2 ──RX ISR──→ 环形缓冲(每路144KB)    │──→ sd_writer线程
              │          │                            │            │      │批量块写
  RS485 A/B ──[SP3485]───┤  USART2 ──RX──→ 扩展通道框架 │            │      ▼
  TTL串口 ───────────────┤  UART4  ──RX──→             │            │  DFS/SDMMC1 (4-bit)
  IMU ──────[I2C1]───────┤                             │            │      │fsync 500ms
                         │  TIM2 @1MHz ──微秒时间戳     │            │      ▼
                         │  RTC+LSE  ────绝对时间       │            │  microSD (FatFs)
  USB ──[PA11/12 OTG]────┤  USB OTG ──CDC──→ usb_proto线程(帧流+命令)  │
  SWD ───────────────────┤  FinSH线程(调试命令)  app_main线程(状态机/LED/按键) │
                        └──────────────────────────────────────────────┘
```

设计原则（贯穿所有模块）：

1. **快慢分离**：延迟敏感路径（CAN 收帧→入队）只在中断内完成；一切阻塞操作（SD 写、USB 发、文件操作）都在线程里；
2. **SD 为权威数据源**：USB 实时流是"尽力而为"的观察通道，满载时允许降级（见 USB 协议文档），完整性永远以 SD 记录为准；
3. **单方向数据流**：CAN 数据只从 ISR → 环形缓冲 → 写盘/上行，无回环，无锁设计；
4. **掉电第一**：任何时刻断电，文件系统可恢复，已 fsync 数据完好。

## 2. 数据通路详设

### 2.1 CAN 接收路径（零丢帧关键路径）

```text
FDCAN RX FIFO0 达水位(16条) → 中断
  └─ ISR: 逐条读出 FIFO 元素
       ├─ 读 TIM2 计数器 → µs 时间戳（入队前读， jitter ≤ 数 µs）
       ├─ 封装记录头(12B) + 数据 → 推入本通道 SPSC 环形缓冲
       └─ rt_sem_release(sd_sem) [rt_interrupt_enter/leave 保护, 仅当缓冲过水位]
主循环外无任何拷贝：sd_writer 线程被信号量唤醒 → 从两路环形缓冲搬运到 64KB DMA 暂存
  → DFS write() → 计数满 500ms 调 fsync → 更新 STATS
```

- ISR 目标耗时 ≤ 5 µs/条（读 FDCAN Message RAM + 环形缓冲拷贝）；
- 环形缓冲 **SPSC 无锁**：单生产者（FDCAN1 ISR）/单消费者（sd_writer 线程），索引用 volatile + 内存序约束；
- 覆盖策略：缓冲满时**丢最旧**并递增 `drop_old` 计数（进入 EVENT 记录与状态上报）——正常设计下永不触发（见吞吐文档）。

### 2.2 USB 路径（观察通道）

```text
sd_writer 批量搬运环形缓冲时，同时把数据(按流模式过滤/抽样后)推入 USB TX 环(32KB)
usb_proto 线程: TX 环 → CDC 发送(协议封帧+CRC16) ；RX 方向解析命令 → 动作分发
TX 环水位 ≥75% → 触发降级(事件通知主机) ，≥95% → 临时切换 1/N 抽样
```

### 2.3 控制路径（命令）

```text
主机命令包 → usb_proto 解析(校验CRC) → 命令表分发
  ├─ 查询类: 读状态结构体 → 回包
  ├─ 配置类: 校验合法性 → 写运行参数 (+ 可选持久化到 witlog.cfg)
  ├─ 动作类: START/STOP_REC → 置状态机事件 → app_main 线程执行状态迁移
  └─ 发送类: 写 FDCAN TX buffer / 注册周期帧句柄
```

### 2.4 扩展通道路径（v1 框架）

UART4/RS485: RX 中断 → 环形缓冲（与 CAN 同一记录格式，type=UART_RX，ch 区分）→ 同一写盘管线。IMU: app_main 定时读取（默认 100 Hz）→ type=IMU 记录。扩展通道吞吐需求极小，与 CAN 共享缓冲预算（见吞吐文档预留 16KB）。

## 3. RT-Thread 线程规划

> RT-Thread 优先级数值**越小越高**。SysTick=OS tick (1 kHz)，HAL 时基=TIM6（避免冲突）。

| 线程 | 优先级 | 栈 | 周期/触发 | 职责 |
|------|--------|-----|-----------|------|
| t_sd_writer | 10 | 2 KB | sd_sem 信号量 / 水位 | 两路环形缓冲→DMA 暂存→写盘→fsync→USB 环投递 |
| t_usb_proto | 20 | 3 KB | CDC 事件 + TX 环水位 | 协议封帧/解帧、命令分发、流控降级 |
| t_app_main | 25 | 2 KB | 事件队列 20ms 轮询 | 记录状态机、按键 LED、IMU 采样、配置加载 |
| t_finsh | 20 | 4 KB | FinSH 默认 | 调试命令（status/du/can 等自定义命令注册） |
| tidle/timer | 系统 | — | — | RT-Thread 系统线程 |

线程总栈 ~11KB + 系统堆 64KB（放 DTCM，见 §5）。

## 4. 中断规划

| 中断源 | NVIC 抢占优先级 | 职责 | 预算 |
|--------|----------------|------|------|
| FDCAN1 line0 | 1 | RX FIFO0 水位抽水 | ≤5µs/条 |
| FDCAN2 line0 | 1 | 同上 | 同上 |
| TIM2 | 2 | （预留，周期任务标记） | — |
| USB OTG FS | 3 | CDC 收发 | ≤20µs |
| SDMMC / DMA | 4 | 块传输完成 | ≤10µs |
| USART2/4 RX | 5 | 扩展通道收字节 | ≤3µs |
| EXTI(按键) | 6 | 按键事件入队 | ≤3µs |

最坏中断频率 ≈ 2×~4k fps(FDCAN 水位抽水后 ≈ fps/16) + 1kHz tick + USB ≈ < 1k 次/s，CPU 占用 < 5%（550MHz M7，定量见吞吐文档 §4）。

## 5. 内存布局（564KB 总量）

```text
┌ DTCM 128KB ─────────────────────────────┐  CPU 专用，最快
│ 系统堆 64KB(线程栈/消息队列)  全局热数据  │  ⚠️ 禁止放 DMA 缓冲
├ System RAM 432KB ───────────────────────┤  DMA 可访问
│ CAN1 环形缓冲      144KB  (cached, CPU-only 拷贝)      │
│ CAN2 环形缓冲      144KB                              │
│ USB TX 环           32KB  (MPU 非缓存区)              │
│ SD DMA 暂存         64KB  (MPU 非缓存区, 32B 对齐)    │
│ 扩展通道/杂项       ~16KB                             │
│ 余量                ~32KB                            │
├ Backup SRAM 4KB (VBAT) ────────────────┤  掉电保持(VBAT 供电时)
│ 会话续记 Cookie(会话ID+段号+校验)        │
└────────────────────────────────────────┘
```

### D-Cache / DMA 一致性策略（H7 关键设计点）

| 缓冲 | 位置 | 一致性手段 |
|------|------|-----------|
| FDCAN Message RAM | 外设自有 RAM（Device 内存） | 不经 D-Cache，无需处理 |
| CAN RX 环形缓冲 | cached | ISR(CPU)写 → writer(CPU)读，纯 CPU 访问，无 DMA 参与 |
| SD DMA 暂存 64KB | **MPU 标记非缓存** | DMA 直接访问，CPU 拷贝用写入直通，零维护成本 |
| USB TX 环 | **MPU 非缓存** | 同上 |

选型说明：非缓存区方案牺牲少量 memcpy 速度（~1MB/s 量级完全无感），换取**零 cache 维护代码**和确定性——对记录仪这种"长期无人值守"设备，确定性 > 性能余量。

## 6. 时间戳服务

- **TIM2**: 32-bit @1MHz（APB 定时器时钟 275MHz/275？由 CubeMX 定 1MHz 分频），µs 计数，**约 71.6 分钟回绕**；
- **RTC**: 秒级绝对时间，LSE 驱动（自制板）；上位机 SET_TIME 同步；
- **对齐机制**：开机时和每 10 秒，写一条 SYNC 记录 `{rtc_epoch, ts_us_now}`；PC 端用相邻 SYNC 记录把每帧 `ts_us` 换算为绝对时间（线性插值，TIM2 漂移可忽略：HSE ±20ppm → 10s 内漂移 ≤200µs）；
- **回绕处理**：writer 检测 ts 单调递减 > 阈值即判定回绕，自动插入额外 SYNC 记录（详见数据格式文档 §4）；
- 开发板无 LSE 的降级：RTC 走 LSI（漂移大），依赖 USB 定期 SET_TIME；逻辑精度（µs 级帧间）不受影响（详见引脚文档 §5）。

## 7. 记录控制状态机（app_main 线程）

```text
            +-------+  KEY1/命令 START   +--------+   建文件成功
   上电 ──→ │ IDLE  │ ─────────────────→ │ PREP   │ ──────────→ +---------+
            |       | ←───────────────── | (建目录 │             │ RUNNING │
            +---+---+   建文件失败        |  文件)  | ←────────── +----+----+
                │                        +--------+   STOP/按键     │ 256MB 分段
                │ 挂载失败                                                    │
                ▼                    +-----------+   关闭完成(写CRC+SYNC)   ▼
            +-------+   换卡/重试    | STOP_FLUSH| ←──────────────────────+------+
            | ERROR | ─────────────→ (写统计+   | ──────────────────────→ IDLE
            +-------+                |  文件CRC) |
                                     +-----------+
```

- `auto_start` 配置项决定上电是否自动进入 PREP；
- PREP：挂载检查 → 创建 `/LOG/<session>/` → 写 SESSION.INI → 打开 S%04d.WLG → 写文件头 + 首条 SYNC；
- ERROR 态 LED 双闪，错误码入 EVENT 记录 + 串口日志；支持热插拔检测重新挂载；
- **续记**：上电后先查 Backup SRAM Cookie（有效则跳过全盘扫描）→ 扫描 `/LOG` 最新会话 → 按 `resume_policy`（default=新会话）决定续段或新会话；Cookie 只是加速，文件系统扫描是权威路径（卡可能被拔到别的设备）。

## 8. bus-off 与错误管理

| 事件 | 处理 |
|------|------|
| bus-off | FDCAN 使能自动恢复（AutoRetransmission + BusOff 恢复）；PSR.BO 置位计数 `busoff_cnt`，EVENT 记录，恢复后继续记录 |
| RX FIFO 溢出（硬件级） | `RF0L` 中断计数 `hw_overrun`——理论不应发生（缓冲设计保证），发生即报告设计缺陷 |
| 环形缓冲满 | 丢最旧 + `drop_old` 计数（见 2.1） |
| SD 写失败/挂载失败 | 重试 N 次 → 状态机 ERROR，LED 报错，等待换卡 |
| 卡剩余空间 < 128MB | EVENT 告警 + LED 慢闪提示 |

## 9. 配置管理

- 存储位置：`/CONFIG/witlog.cfg`（INI 风格文本，可直接记事本编辑）；
- 内容：双通道波特率/模式、流模式、fsync 周期、分段大小、auto_start、resume_policy、LED 模式；
- 加载顺序：编译内置默认 → 卡上文件覆盖 → USB SET_CONFIG 运行时覆盖（可选持久化）；
- 写入策略：先写 `.tmp` + fsync + rename，保证断电不产生半截配置。

## 11. 启动流程

```text
Reset → SystemInit(550MHz 时钟树) → RT-Thread 启动 → main:
  1. io_if 初始化(LED/按键)      2. time_if 初始化(TIM2/RTC)
  3. storage_if 挂载 SD          4. cfg_load
  5. can_if open ×2 (按配置)     6. usb_proto 启动(CDC 枚举)
  7. 续记扫描 → 决定会话         8. auto_start ? PREP : IDLE
  9. 打印启动横幅(FinSH 可用)    10. app_main 进入状态机循环
```
