## 1. 最坏工况帧率计算

CAN FD 帧传输时间 = 仲裁段@仲裁速率 + 控制段 + 数据段@数据速率 + CRC + 帧间隔，含填充位（数据段按 +20% 包络，仲裁段按 +20%）。

单帧耗时（64 字节数据、29-bit ID）：

```text
T_frame ≈ (40 bit @ 500k) + (11 bit @ 500k) + (614 bit @ 数据速率) + (21 bit @ 数据速率) + ~15 bit 混合
        ≈ 102 µs + (635 bit / 数据速率)
```

| 配置（仲裁/数据） | 单帧耗时 | 单路帧率上限 | 双路合计 |
|-------------------|----------|--------------|----------|
| 500k / 2M（设计目标） | ~356 µs | ~2.8k fps | ~5.6k fps |
| 500k / 5M（工程目标） | ~229 µs | ~4.4k fps | ~8.8k fps |
| 500k / 8M（探边界） | ~204 µs | ~4.9k fps | ~9.8k fps |
| 经典 CAN 1M（对比） | ~130 µs | ~7.7k fps | — |

> 数值为 ±20% 包络（填充位依赖 ID 内容），M2.5 用 CAN 工具满载对发实测修正。

## 2. 记录数据速率（写入/上行带宽需求）

单条记录 ≤ 12B 头 + 64B 数据 = **76B**（含 4 字节对齐间隙按 76~80B 计）。

| 工况 | 数据速率（SD 写入需求） |
|------|------------------------|
| 2× 500k/2M 满载 | 5.6k fps × 76B ≈ **0.43 MB/s** |
| 2× 500k/5M 满载 | 8.8k fps × 76B ≈ **0.67 MB/s** |
| 2× 500k/8M 满载 | 9.8k fps × 76B ≈ **0.75 MB/s** |
| 加 IMU(100Hz×24B)+串口(115200×0.5) | + ~5 KB/s（忽略不计） |

**容量换算**：0.43 MB/s → 1.55 GB/h；32GB 卡设计目标工况可连续记录 ~20 h，5M/8M 工况 ~12 h。分段大小 256MB（约 10 分钟满载 / 数小时常规负载）。

## 3. SD 写入带宽核算

| 项 | 数值 | 结论 |
|----|------|------|
| SDMMC1 4-bit High-Speed @50MHz | 理论 25 MB/s，实测裸盘 15~20 MB/s | — |
| DFS/FatFs 开销后持续写入（小批量块写） | 预期 4~8 MB/s（M2.3 实测） | — |
| 需求（8M 满载） | 0.75 MB/s | **≥10 倍余量** ✅ |

结论：SDMMC 带宽远超需求；**真正的瓶颈是 SD 卡内部偶发长阻塞**（见 §4），不是带宽。

## 4. 环形缓冲深度核算（零丢帧核心）

丢帧的唯一场景：`SD 卡长阻塞时间 × 数据速率 > 环形缓冲容量`。

SD 卡阻塞实测经验：连续写入时偶发 **50~500 ms**（卡内 GC/磨损均衡），质量差的卡更严重、且随老化恶化。

```text
缓冲需求 = 最坏阻塞时间 × 最坏数据速率 + 安全余量
```

| 工况 | 288 KB 缓冲（2×144KB）可吸收的阻塞时间 |
|------|----------------------------------------|
| 2M 满载（0.43 MB/s） | **670 ms** ✅ 覆盖 500ms 包络 |
| 5M 满载（0.67 MB/s） | 430 ms ✅ |
| 8M 满载（0.75 MB/s） | 384 ms ✅（包络边缘，接受：丢帧有计数与上报，非静默） |

**结论：每路 144KB 环形缓冲**（2×144=288KB），满足 500ms 卡阻塞包络下的零丢帧。缓冲配置为编译期常量（`CAN_RING_SIZE`），M2.3 实测后如需调整在此回改。

辅助策略（纵深防御）：
1. writer 检测到某卡写入耗时 > 100ms 时记录 STATS（`write_ms` 柱状桶），提供卡健康观测；
2. `drop_old`/`hw_overrun` 计数任何非零 → EVENT 记录 + LED 提示 + USB 状态上报；
3. 卡选型要求高耐久型（选型文档 §3），写入寿命按 0.43MB/s × 工作时长评估：高耐久卡（~3000 P/E，32GB）全速写入可运行 > 2 年。

## 5. USB FS CDC 带宽核算（Q4 决策依据）

| 项 | 数值 |
|----|------|
| USB FS theoretical | 12 Mbps = 1.5 MB/s |
| CDC bulk 64B 包实际有效吞吐（含协议封装） | **0.6 ~ 0.9 MB/s**（经验值，M2.7 实测） |
| 设计目标工况实时流需求 | 0.43 MB/s → **基本可承载**（留有余量） |
| 5M/8M 满载 | 0.67~0.75 MB/s → **超限，触发降级** |

**Q4 决策：v1 采用 USB FS，不预留 ULPI HS PHY。**

降级策略（详见 USB 协议文档 §6）：
- 流模式 `ALL`（回放所有帧）：仅设计目标工况可用；
- 流模式 `FILTERED`（仅主机过滤器匹配帧）：按需降带宽；
- 流模式 `SAMPLED`（1/N 抽样）：满载工况的观察模式；
- 任何降级不丢 SD 数据——SD 永远是完整权威记录。
- v1.x 选项：H723 OTG HS + ULPI PHY（USB3300）可到 ~30 MB/s；或改用带 Ethernet 的 H743 做千兆流。均不影响 v1 架构（TX 环与降级逻辑已是独立模块）。

## 6. CPU 负载核算

550 MHz Cortex-M7，取保守每条指令周期数：

| 开销源 | 频率 | 单次成本 | CPU 占用 |
|--------|------|----------|----------|
| FDCAN ISR（水位抽水，平均 16 条/次） | ~600 次/s | 16×5µs = 80µs | **4.8%** |
| RT-Thread tick + 调度 | 1 kHz | ~2µs | 0.2% |
| USB 中断 + 协议 | ~10k pk/s | ~1µs | 1% |
| sd_writer 搬运+封帧 | 0.43 MB/s | memcpy ~4 cycles/B | 0.3% |
| FS/SDMMC 驱动开销 | — | — | ~2% |
| **合计** | | | **< 10%** ✅ |

结论：550MHz M7 负载极轻，8M 探边界工况也 <15%，无需优化手段（DMA 搬运环形缓冲属 v1.x 优化项）。
