# 数据格式定义（SD 卡）

| 文档状态 | 🔄 待评审 → 通过即冻结 |
|----------|----------|
| 版本 | v0.1 |
| 日期 | 2026-11-09 |
| 关闭开放问题 | **Q7**：SD 数据文件格式 = 自定义紧凑二进制（.WLG），PC 端 `tools/wlconv.py` 转换为 CSV / Vector ASC / candump 格式 |

> 决策理由：自定义二进制写入开销最小（无转义/无文本化）、每条定长头、解析单向；生态兼容交给 PC 端转换工具承担（`python-can` 可直接输出 blf/asc/csv）。USB 实时流**复用同一记录格式**（协议文档 §5），固件只维护一种封帧。

## 1. SD 卡目录结构

```text
/ (microSD, FAT32)
├── CONFIG/
│   └── witlog.cfg              设备配置（INI 文本，架构文档 §9）
├── LOG/
│   └── 20261109T1530_S01/      会话目录 = 启动时间 + 会话序号
│       ├── SESSION.INI         会话元数据（文本）
│       ├── S0001.WLG           数据段文件
│       ├── S0002.WLG
│       └── ...
└── SYSTEM/                     诊断信息（可选，v1 仅 EVENT 摘要）
```

### SESSION.INI（示例）

```ini
[session]
uid = 20261109T1530_S01
start_utc = 2026-11-09 15:30:00
fw_ver = 1.0.0
proto_ver = 1
serial = WITLOG-0001
status = open            ; open | closed | aborted
segments = 3

[ch1]
mode = fd                ; classic | fd
arb_bps = 500000
data_bps = 2000000

[ch2]
mode = fd
arb_bps = 250000
data_bps = 1000000
```

## 2. WLG 文件结构

```text
┌────────────────────────────┐ offset 0
│ 文件头（512B，见 §2.1）      │
├────────────────────────────┤ offset 512
│ 记录 1 [12B头 + 0~64B数据]  │
│ 记录 2 ...                  │   4 字节对齐（数据不足补 0x00，len 字段为准）
│ ...                         │
├────────────────────────────┤ （正常关闭时追加）
│ STATS 记录 (type=5)         │
│ CRC32 记录 (type=7)         │  ← 数据区(头之后到本记录前)的 CRC32
└────────────────────────────┘
```

**无 CRC 记录的文件 = 异常中断文件**（掉电/拔卡），PC 工具标记 `unclosed` 并按可得数据恢复——这是掉电检测的主要手段。

### 2.1 文件头（512 字节，小端）

| 偏移 | 类型 | 字段 | 说明 |
|------|------|------|------|
| 0 | char[4] | magic | `"WLG\x01"` |
| 4 | u16 | hdr_ver | 头版本 = 1 |
| 6 | u16 | rec_ver | 记录格式版本 = 1 |
| 8 | u32 | hdr_size | = 512 |
| 12 | u32 | file_seq | 段号（会话内，1 起） |
| 16 | char[24] | session_uid | 会话 UID（同 SESSION.INI） |
| 40 | u64 | start_epoch_s | 建文件时 RTC 秒 |
| 48 | u32 | ts_base_us | 建文件时 TIM2 计数值 |
| 52 | u32 | fw_ver | 固件版本 |
| 56 | u32 | cfg_crc | 配置摘要 |
| 60 | u32×2 | ch1_bps | arb<<32 \| data（打包） |
| 68 | u32×2 | ch2_bps | 同上 |
| 76 | u32 | reserved[...] | 0 填充至 508 |
| 508 | u32 | hdr_crc32 | 偏移 0~507 的 CRC32 |

## 3. 记录格式

### 3.1 记录头（12 字节，小端）

| 偏移 | 类型 | 字段 | 位定义 |
|------|------|------|--------|
| 0 | u32 | ts_us | TIM2 µs 计数（低 32 位，绝对时间经 SYNC 换算，§4） |
| 4 | u32 | id_flags | [31]=EXT(29位ID) [30]=RTR [29]=FDF [28]=BRS [27]=ESI [26:0]=ID |
| 8 | u16 | len | [5:0]=数据长度 0~64；[15:6]=0 |
| 10 | u8 | type | 见 §3.2 |
| 11 | u8 | ch | 0=CAN1 1=CAN2 2=RS485 3=TTL 0xF=系统 |

### 3.2 记录类型表

| type | 名称 | 数据区 | 说明 |
|------|------|--------|------|
| 0x00 | CAN_RX | CAN 数据 ≤64B | 总线收到的帧 |
| 0x01 | CAN_TXE | ≤64B | 本机发送成功回执（TxEvent FIFO） |
| 0x02 | UART_RX | ≤64B | 扩展串口原始字节流（分包 ≤64B） |
| 0x03 | IMU | 14B: i16×3 accel + i16×3 gyro + u16 reserved + u16 seq | 固定速率采样 |
| 0x04 | SYNC | 8B: u32 rtc_epoch_s + u32 ts_us_at_sync | 时间对齐锚点，开机 + 每 10s |
| 0x05 | STATS | 见 §3.3 | 段关闭时写入 |
| 0x06 | EVENT | 16B: u32 code + u32 arg + u32 ts + u32 reserved | 错误/状态事件 |
| 0x07 | FILE_CRC | u32 | 数据区 CRC32（关闭标记） |

### 3.3 STATS 记录数据区（28B）

```text
u32 rec_count        本段记录条数
u32 drop_old         环形缓冲丢旧计数
u32 hw_overrun       FDCAN FIFO 硬件溢出计数
u32 busoff_cnt[2]    双通道 bus-off 次数
u32 usb_drop         USB 流降级丢弃计数
u32 write_ms_max     最慢单次写盘耗时 ms
```

## 4. 时间戳换算规则（PC 端与固件共同遵守）

1. 每条记录的 `ts_us` 是 TIM2 自由计数，**71.6 分钟回绕**；
2. writer 在检测到 ts 相对前一条**递减超过 2^31** 时判定回绕，立即插入一条 SYNC 记录（保证回绕点两侧都有锚点）；
3. PC 端换算：取记录前后最近的 SYNC 锚点 `(epoch_s, ts_anchor)`，`abs_time = epoch_s + (ts_us − ts_anchor)×1e-6 + 回绕补偿(±2^32µs)`；
4. 精度：锚点间 10s，TIM2 HSE 漂移 ±20ppm → 换算误差 ≤ 0.2ms，满足验收（帧间 ≤100µs 为原始 ts 直接可比，不依赖换算）。

## 5. 分段与续记规则

| 规则 | 内容 |
|------|------|
| 分段触发 | 段大小 ≥256MB，或 STOP，或每段最长 24h（防时钟漂移锚点稀疏——其实 SYNC 已覆盖，此条保险） |
| 段命名 | `S%04d.WLG`，会话内连续编号 |
| 上电恢复 | Backup SRAM Cookie（uid+段号+CRC）加速定位 → 扫描 `/LOG` 最新会话目录为权威 |
| 续记策略 | `resume_policy = new`（默认）：旧会话标 `aborted`，开新会话目录；`resume = continue`：同目录续段（段号接续），文件头 start_epoch 为新段起点 |
| 半截文件 | 不改名不截断——CRC 记录缺失即"unclosed"标记，PC 工具负责恢复边界（重扫记录头对齐） |

## 6. PC 端转换工具约定（tools/wlconv.py）

```text
用法: python wlconv.py <session_dir|file.WLG> [--to csv|asc|candump] [--dbc file.dbc] [--out dir]
功能: - unclosed 文件自动恢复（记录头 magic 对齐扫描）
      - ts → 绝对时间（SYNC 换算 §4）
      - --dbc: 用 cantools 解码物理值输出到 CSV 附加列
      - 校验 FILE_CRC，统计丢条（对比 STATS）
```
