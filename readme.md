# WIT_LOGs — 高性能 CAN/CAN FD 数据记录仪

> 2 路 CAN FD（兼容经典 CAN）数据记录仪：多通道总线数据带微秒级时间戳写入 SD 卡，通过 USB 向上位机提供实时数据流与分析控制通道，可扩展串口（RS485）与 IMU 传感器记录。
> 本仓库包含该项目的**全部软硬件开发流程文档与代码**，按阶段顺序推进。

## 二、已确定的关键决策（M0 评审已关闭）

| 决策项 | 结论 | 依据 |
|--------|------|------|
| 产品定位 | **高性能 CAN/CAN FD 记录仪** | 2 路采集 + 上位机分析 + 可扩展串口/IMU |
| CAN 通道数 | **2 路 CAN FD**（兼容经典 CAN） | 对标主流商用记录仪；第 3 路 FDCAN 硬件预留 |
| 分析功能定位 | **上位机分析为主** | 固件做记录+实时流+收发执行，DBC 解析/图形/统计在电脑端 |
| 主控平台 | **STM32H723VGT6**（Cortex-M7 @550MHz，3× FDCAN，564KB RAM，2× SDMMC） | 唯一同时满足多路 FD + 原生 SDMMC + 大 RAM 缓冲的候选；F103/F407 无 FDCAN 已淘汰 |
| 开发板 | **WeAct H723VGT6 核心板**（淘宝 ¥88–115，现货） | "先开发板后画板"路线 |
| 存储 | **SDMMC + FatFs R0.15**，microSD ≤32GB | 原生 SDMMC 保证满载写入吞吐 |
| 工具链 | **EIDE (VSCode) + arm-none-eabi-gcc + CubeMX** | 与本仓库 git 工作流契合 |
| 软件平台 | **RT-Thread 标准版 5.x**（FinSH shell + DFS 文件系统） | 2026-11-09 决策；线程模型见[技术选型 §7](docs/00_立项/02_技术选型.md) |
| 显示 | **v1 不做 OLED**（LED+按键交互），预留扩展 | 先保证核心记录功能 |
| CAN 收发器 | **FD 型收发器**（TJA1044GT / MCP2562FD 级别），×2 | ⚠️ 经典收发器（TJA1050/MCP2551/SN65HVD230）不支持 FD 数据段高速率，不可用 |

## 四、开发流程说明

每个阶段遵循同一套节奏：

1. **输入**：阅读上一阶段产出 + 本阶段入口文档中的任务清单；
2. **执行**：逐项完成任务，记录/数据/报告写入本阶段目录；
3. **评审**：对照文档中该阶段的**退出标准（DoD）**逐条检查；
4. **归档**：更新 `readme.md` 状态表与相关文档修订记录；
5. **进入下一阶段**。

### 各阶段要点

- **M0 立项** ✅：需求、选型、计划已评审关闭。
- **M1 系统设计**：系统框图与数据流（CAN 中断 → 环形缓冲 → SD 写入 / USB 上行）、FDCAN Message RAM 3 路分配计算、引脚分配表、SD 卡文件格式、USB 主机协议、吞吐与缓冲定量设计。**设计冻结后进入编码**。
- **M2 开发板固件**：WeAct H723 板上依次实现：工程搭建 + RT-Thread 内核集成 → FinSH 调试基建 → SD 存储（DFS/裸 FatFs 适配层）→ RTC+微秒时间戳 → FDCAN 驱动 → 写入管线（满载丢帧测试）→ USB CDC 协议 → IMU/串口扩展 → 整机联调。每步在 `docs/03_软件开发/开发记录/` 留记录。
- **M3 硬件设计**：原理图（2× CAN 收发器 + TVS/共模 + 终端电阻跳线、12~24V DC-DC、SDMMC 座、USB、RS485、IMU 焊盘）→ PCB → 打样 → 焊接。
- **M4 硬件验证**：PCB 调试、固件移植、改版记录。
- **M5 测试验证**：满载丢帧、掉电、72h 连续运行、时间戳精度。
- **M6 发布**：归档 + 使用说明。
